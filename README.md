# rknKID монитор

Раз в N минут обходит источники и кидает новое в тг-чат через бота. Только стандартный Python 3.9+, ставить ничего не надо.

Что ловит:
- **У1, первоисточники:** новости РКН, новости Госдумы (по ключевым словам), список экстремистских материалов Минюста (дифф страницы), отчёт прозрачности Яндекс Музыки (дифф), и опционально **пропавшие треки** у выбранных рэперов на Яндекс Музыке.
- **У2:** Коммерсантъ, РБК, Фонтанка, Хабр, CNews (RSS по ключевым словам), тг Кода Дурова.
- **У3 / сбои:** IODA (сбои связи по РФ), NetBlocks.
- Любой публичный тг-канал через `t.me/s/<канал>` (Мизулина, каналы рэперов, «На связи» и т.д.): добавь строку в `sources.json`.

Метки в сообщениях: 🔴 У1 можно постить сразу, 🟡 У2 нужен второй источник, ⚪ У3 сначала проверить (правило из брифа, 5.2).

## 1. Бот и чат (5 минут)
1. @BotFather → `/newbot` → получаешь токен `123456:ABC...`.
2. Создай приватную группу «rknkid радар», добавь туда бота.
3. Напиши в группу что угодно, открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьми `chat.id` (у групп он с минусом, типа `-100123...`).

## 2. Проверка локально
```bash
python3 monitor.py --dry-run      # первый проход только запоминает текущее, ничего не шлёт
python3 monitor.py --dry-run      # второй и дальше показывают новое
```
Видишь в консоли `[id] ошибка` — источник не открылся (см. «Гео» ниже).

## 3. Где крутить

**Гео-засада.** Сайты `*.gov.ru` (РКН, Минюст, Дума) и API Яндекс Музыки часто не пускают зарубежные IP. Значит У1 надо гонять с российского IP: твой комп или российский VPS. Остальное работает откуда угодно.

**Вариант А, свой комп или RU-VPS (рекомендую, это и есть «быть первыми»):**
```bash
export TG_BOT_TOKEN=123:ABC TG_CHAT_ID=-100123
crontab -e
*/5 * * * * cd /path/to/monitor && TG_BOT_TOKEN=... TG_CHAT_ID=... python3 monitor.py >> monitor.log 2>&1
```
Или без cron: `python3 monitor.py --loop 300` в tmux/screen. На винде: Планировщик заданий, раз в 5 минут `python monitor.py`.

**Вариант Б, GitHub Actions (так сейчас и работает, репо публичный — минуты бесплатные):**
1. Settings → Secrets and variables → Actions: `TG_BOT_TOKEN`, `TG_CHAT_ID`.
2. Actions → monitor → Run workflow.
Один запуск крутится ~5ч45м с проходом каждые 5 минут (плюс напоминалки из `reminders.json`), потом перезапускает сам себя. Cron раз в 2 часа — страховка, если цепочка оборвётся. У1-сайты оттуда не открываются.

Оптимально: Б для всего, плюс А с отдельным файлом только для У1 (`--sources sources_ru.json --state state_ru.json`).

## 4. Настройка `sources.json`
- `keywords` — общий фильтр (подстрока, без регистра). Пост проходит, если есть хоть одно слово.
- У источника: `"filter": false` — слать всё; `"keywords": [...]` — свой список; `"enabled": false` — выключить; `level` — 1/2/3.

Типы:
| type | поля | что делает |
|---|---|---|
| `rss` | `url` | RSS/Atom |
| `telegram` | `channel` | публичный канал через t.me/s |
| `page` | `url`, `pattern` | регулярка с группами `link`, `title` (опц. `id`) → каждое совпадение = пункт |
| `page` | `url`, `min_len` | без `pattern`: новые строки текста страницы = пункты |
| `ioda` | `entity_code` | алерты IODA по стране |
| `yandex_artist` | `artists`, `names` | id артистов или имена (резолвятся поиском один раз, кэш в state.json, в логе видно, кого нашёл); шлёт 🚫 ПРОПАЛО, если трек исчез или стал недоступен |

**Пропавшие треки** (идея из брифа 5.4, главный способ узнавать раньше СМИ): открой артиста на music.yandex.ru, число из адреса `music.yandex.ru/artist/<id>` добавь в `artists`, поставь `"enabled": true`. Работает только с RU IP. Если API вдруг отдал пустоту, массовое «пропало» не шлётся (защита от ложняка).

В каждом сообщении время: когда появилось в источнике (если источник его отдаёт: RSS, тг, IODA) и когда поймали, по Тюмени. Всё отправленное пишется в `detections.csv` (UTC) — по нему считаем, насколько мы первые.

Читаем тг только через публичное превью t.me/s, без юзербота и без входа в аккаунт; отправка через Bot API. Аккаунт-владельца @rknkid в монитор не подключать никогда: бан юзербота = потеря канала.

Если источник падает 6 проходов подряд, бот один раз пишет ⚠️ в чат.

## Статус проверки
Код прогнан на тестовых данных: RSS/Atom, тг-превью, дифф страниц, исчезновение трека, защита от пустого ответа, алерт о мёртвом источнике. С живыми сайтами из облака проверить не вышло (там закрыт доступ к этим доменам), поэтому первый `--dry-run` у тебя покажет, какие адреса надо поправить. Регулярки для РКН и Думы написаны под их текущую разметку ссылок (`/news/rsoc/newsNNNN.htm`, `/news/NNNN/`), если сайт поменяют — правится одна строка.

Не коммить токен в репо. `state.json` — память о том, что уже видели; удалишь — следующий проход снова «засеет» без отправки.
